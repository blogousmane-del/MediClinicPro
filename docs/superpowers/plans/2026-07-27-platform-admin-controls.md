# Platform Admin Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Platform Admin (Super Admin) console real per-clinic controls — an unlimited-staff override, a clinic suspension kill switch, cross-clinic user deactivation — plus search/filter on its three data tables, replacing what is currently 100% read-only.

**Architecture:** Two new boolean columns on `clinics` (`unlimited_staff`, `suspended_by_platform`). Three new mutation endpoints in `backend/routes/platform.js` (already `superAdminOnly`-gated). `backend/utils/plans.js`'s staff-limit check gains an override parameter, threaded through its three existing call sites. `backend/middleware/auth.js`'s subscription-gate logic gains a suspension check, with `/api/platform` routes exempted from both the expiry and suspension blocks (self-lockout guard — see Task 4). Frontend: `frontend/src/pages/PlatformAdmin/PlatformAdminPage.tsx`'s Cliniques/Utilisateurs/Abonnements sections gain client-side search/filter and, for Cliniques/Utilisateurs, row actions via an expandable "Gérer" row (matching the pattern already used for support tickets in this same file).

**Tech Stack:** Express + `@supabase/supabase-js` (backend), React 19 + TypeScript (frontend), plain CSS with inline `style={{}}` (this project's established convention — no Tailwind, no CSS modules).

## Global Constraints

- All user-facing strings in French (CLAUDE.md — this app is French-only).
- Every table query filters `.eq('clinic_id', req.user.clinicId)` except `backend/routes/platform.js`, the established cross-clinic exception (gated by `superAdminOnly`, not by role).
- No automated test suite exists in this repo (confirmed in CLAUDE.md) — every backend task's verification step is a `curl` command with the exact expected JSON; every frontend task's verification is `npm run build` + `npm run lint` plus a manual dev-server check.
- Known schema-drift constraint: no session has DDL access to the live Supabase database. New columns go in `backend/supabase_schema.sql` (source of truth) but will error against the live DB (`42703`, undefined column) until a human runs the equivalent `ALTER TABLE` by hand in the Supabase SQL Editor. Task 1 states the exact statement to hand off.
- Mutations write an `activity_logs` row (existing convention in every route file). The three new `platform.js` endpoints are the first mutation-logging code in that file besides the existing ticket-status endpoint.
- **Self-lockout guard (see Task 4):** `/api/platform` routes must stay reachable to a Super Admin even if their own clinic is expired or suspended — otherwise a Super Admin could lock themselves out of the one console that could fix it.
- **Scope boundary:** the unlimited-staff override lifts only the staff *count* limit (`isStaffLimitReached`) — it must never touch `isRoleAllowedForPlan`. A Starter clinic with the override still cannot add a `pharmacist`/`lab_tech`/`manager`/`nurse`.

- [ ] **Step 2: Add the three new endpoints**

In the same file, add these three routes right before the final `module.exports = router;` line:

```js
// PUT /api/platform/clinics/:id/staff-override
// Grant or revoke a manual exception to this clinic's plan-based staff COUNT
// limit — independent of clinic.plan itself. Does NOT touch role
// restrictions (isRoleAllowedForPlan is untouched, see utils/plans.js) —
// this is unlimited accounts, not a backdoor around role gating.
router.put('/clinics/:id/staff-override', async (req, res) => {
  try {
    const { unlimited } = req.body;
    if (typeof unlimited !== 'boolean') {
      return res.status(400).json({ error: "Le champ 'unlimited' doit être un booléen." });
    }

    const { data: clinic, error: clinicError } = await supabase
      .from('clinics')
      .select('id, name')
      .eq('id', req.params.id)
      .maybeSingle();
    if (clinicError) throw clinicError;
    if (!clinic) {
      return res.status(404).json({ error: "Clinique introuvable." });
    }

    const { error: updateError } = await supabase
      .from('clinics')
      .update({ unlimited_staff: unlimited })
      .eq('id', req.params.id);
    if (updateError) throw updateError;

    // user_id here is the acting Super Admin, who belongs to a DIFFERENT
    // clinic than clinic_id below — the one deliberate place in this app
    // where activity_logs.user_id's own clinic and the row's clinic_id
    // diverge (safe: activity_logs.user_id is a plain nullable FK to
    // users(id) with no clinic-match constraint).
    await supabase.from('activity_logs').insert({
      clinic_id: clinic.id,
      user_id: req.user.userId,
      action: 'PLATFORM_STAFF_OVERRIDE',
      details: unlimited
        ? "Limite de personnel levée par l'administrateur de la plateforme."
        : "Limite de personnel du plan rétablie par l'administrateur de la plateforme."
    });

    res.json({ success: true, message: "Exception de limite de personnel mise à jour." });
  } catch (error) {
    console.error("Platform staff-override error:", error);
    res.status(500).json({ error: "Erreur lors de la mise à jour de l'exception de personnel." });
  }
});

// PUT /api/platform/clinics/:id/suspend
// Kill switch: suspends or reactivates write access for every user of this
// clinic (enforced in middleware/auth.js). Unlike an expired subscription,
// there is no self-service unlock — only this endpoint can lift it.
router.put('/clinics/:id/suspend', async (req, res) => {
  try {
    const { suspended } = req.body;
    if (typeof suspended !== 'boolean') {
      return res.status(400).json({ error: "Le champ 'suspended' doit être un booléen." });
    }

    const { data: clinic, error: clinicError } = await supabase
      .from('clinics')
      .select('id, name')
      .eq('id', req.params.id)
      .maybeSingle();
    if (clinicError) throw clinicError;
    if (!clinic) {
      return res.status(404).json({ error: "Clinique introuvable." });
    }

    const { error: updateError } = await supabase
      .from('clinics')
      .update({ suspended_by_platform: suspended })
      .eq('id', req.params.id);
    if (updateError) throw updateError;

    await supabase.from('activity_logs').insert({
      clinic_id: clinic.id,
      user_id: req.user.userId,
      action: suspended ? 'PLATFORM_CLINIC_SUSPENDED' : 'PLATFORM_CLINIC_REACTIVATED',
      details: suspended
        ? "Compte suspendu par l'administrateur de la plateforme."
        : "Compte réactivé par l'administrateur de la plateforme."
    });

    res.json({ success: true, message: suspended ? "Clinique suspendue." : "Clinique réactivée." });
  } catch (error) {
    console.error("Platform suspend error:", error);
    res.status(500).json({ error: "Erreur lors de la mise à jour du statut de suspension." });
  }
});

// PUT /api/platform/users/:id
// Cross-clinic activate/deactivate — emergency use (e.g. a compromised
// account) without going through that clinic's own admin. Self-lockout
// guard mirrors the one already in backend/routes/settings.js's own
// PUT /users/:id (a user cannot deactivate their own account there either).
router.put('/users/:id', async (req, res) => {
  try {
    const { active } = req.body;
    if (typeof active !== 'boolean') {
      return res.status(400).json({ error: "Le champ 'active' doit être un booléen." });
    }
    if (parseInt(req.params.id) === req.user.userId) {
      return res.status(400).json({ error: "Vous ne pouvez pas modifier votre propre compte via cette console." });
    }

    const { data: targetUser, error: userError } = await supabase
      .from('users')
      .select('id, clinic_id, name')
      .eq('id', req.params.id)
      .maybeSingle();
    if (userError) throw userError;
    if (!targetUser) {
      return res.status(404).json({ error: "Utilisateur introuvable." });
    }

    const { error: updateError } = await supabase
      .from('users')
      .update({ active: active ? 1 : 0 })
      .eq('id', req.params.id);
    if (updateError) throw updateError;

    await supabase.from('activity_logs').insert({
      clinic_id: targetUser.clinic_id,
      user_id: req.user.userId,
      action: active ? 'PLATFORM_USER_ACTIVATED' : 'PLATFORM_USER_DEACTIVATED',
      details: `Compte de ${targetUser.name} ${active ? 'réactivé' : 'désactivé'} par l'administrateur de la plateforme.`
    });

    res.json({ success: true, message: "Statut de l'utilisateur mis à jour." });
  } catch (error) {
    console.error("Platform user status error:", error);
    res.status(500).json({ error: "Erreur lors de la mise à jour du statut de l'utilisateur." });
  }
});
```

### Platform admin controls (`clinics.unlimited_staff`, `clinics.suspended_by_platform`)
Two Super-Admin-only manual overrides, independent of a clinic's billed plan: `PUT /api/platform/clinics/:id/staff-override` lifts the plan's staff *count* limit for one clinic (`isStaffLimitReached`'s third param) without touching its role restrictions (`isRoleAllowedForPlan` is untouched — unlimited accounts, not a role-gating backdoor); `PUT /api/platform/clinics/:id/suspend` is a kill switch blocking all non-GET requests for every user of that clinic (same enforcement point as `SUBSCRIPTION_EXPIRED` in `middleware/auth.js`, but with no billing-route bypass — paying doesn't lift a suspension, only a Super Admin reversing the toggle does). `PUT /api/platform/users/:id` lets a Super Admin activate/deactivate any user cross-clinic (self-lockout guarded, same pattern as `settings.js`'s own staff endpoint). **Self-lockout guard:** `/api/platform/*` routes are exempt from both the expiry and suspension checks in `middleware/auth.js` — otherwise a Super Admin whose own clinic is expired or suspended could be locked out of the one console able to fix it; safe because every `/api/platform` route is already gated by `superAdminOnly`. All three mutation endpoints write `activity_logs` against the *affected* clinic with `user_id` set to the acting Super Admin — the one place in this app where `activity_logs.user_id`'s own clinic and the row's `clinic_id` deliberately diverge (safe: no clinic-match constraint on that FK).
